Feature experiments

FETCH→DECODE→DISPATCH / RENAME→ISSUE→EXECUTE / COMPLETE→RETIRE

In this implementation, dispatch puts instructions into the window in program order; issue chooses ready operations for execution. Some books use these terms differently. Front-end order stays sequential. Scheduling and completion can change order. Architectural retirement always stays sequential.

Keep the three orders separate

Program order defines the intended computation. Execution order may change when operands are available. Retirement order ensures the visible result, faults, and memory stores behave like the original sequential program. Renaming removes name collisions; it preserves real producer-to-consumer links.

ALU operations execute and register completion in their issue cycle. The multiplier computes a product and delays its result by four register stages; it is not a balanced four-stage arithmetic multiplier. Cache responses add one interface cycle beyond the nominal delay. These details matter when reading the timeline or synthesizing the hardware.
